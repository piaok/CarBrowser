# 方案规划 — LazyLines Browser for Projector

> 阶段2产出 | 日期：2026-05-11

## 1. 需求回顾

基于阶段1需求规格，本项目核心目标是将车机版 LazyLines 浏览器适配到 NVIDIA Shield TV 2017 Pro + BenQ W1070+ 投影仪场景。关键需求：D-pad 全键盘导航、暗色主题、TV Launcher 入口、WebView 分辨率修正、Overscan 安全边距、显著焦点指示器。复用 LazyLines 已有的 WebView 内核/视频检测/ExoPlayer/广告拦截/下载管理。

## 2. 模块划分

| 模块编号 | 模块名称 | 职责 | 依赖模块 |
|----------|----------|------|----------|
| M01 | TV适配基础 | Manifest声明、主题样式、资源限定符、Overscan安全区 | - |
| M02 | D-pad导航框架 | 焦点管理、焦点指示器、导航栏/内容区切换、按键映射 | M01 |
| M03 | TV UI层 | 侧边导航栏、地址栏、书签面板、设置面板、视频工具弹窗 | M02 |
| M04 | WebView适配 | 分辨率修正、TV UA、投影阅读模式(textZoom)、大字体 | M01 |

## 5. 风险评估

| 风险项 | 概率 | 影响 | 应对措施 |
|--------|------|------|----------|
| WebView TV分辨率问题不止setInitialScale | 中 | 高 | 预留备选方案：强制设置WebView viewport meta + setUseWideViewPort |
| D-pad焦点在WebView内网页元素间跳转不可控 | 高 | 高 | WebView内部不拦截焦点，仅在原生UI层做焦点管理；WebView内容靠上下键滚动 |
| ExoPlayer在Shield TV上的codec兼容性 | 低 | 中 | Shield TV Tegra X1硬件解码完善，优先使用硬件解码；如遇HLS问题降级到软件解码 |
| Overscan 10%可能过多/过少 | 中 | 低 | 做成可配置项（Settings中调整），默认10%，投影用户可自定义 |
| 遥控器长按事件延迟导致操作体验差 | 中 | 中 | 使用View.OnKeyListener而非onKeyDown长按，立即响应；设置keyDebounce=150ms |

根据 strict-dev-flow 规则，本项目存在**交互范式重大变化**（触屏→D-pad）和**特定硬件目标**（Shield TV + 投影仪），建议在阶段3架构设计后**插入阶段4：前端UI设计**，包含：

- Design Tokens（暗色主题色彩体系、字体梯度、间距系统）
- D-pad 焦点路线图（各页面焦点流转路径图）
- 各页面交互流程图（首页、浏览、视频、下载、设置）
- Overscan/安全区标注
- 投影仪色彩适配（DLP色域偏移补偿）

后续阶段编号顺延：编码开发→阶段5，单元测试→阶段6，集成验证→阶段7，交付→阶段8。
